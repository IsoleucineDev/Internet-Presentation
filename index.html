El problema

¿Qué es un palíndromo genético?

Una subcadena del genoma que se lee igual de izquierda a derecha que de derecha a izquierda. Por ejemplo ACGGCA no lo es, pero ACGCA sí.

Encontrar el más largo no es trivial: revisar cada centro posible y expandir a mano toma O(n²). Los tres algoritmos de esta presentación resuelven ese mismo reto con estrategias distintas.

Pedro — Manacher

Expandir sin volver a comparar

Primero se inserta un separador # entre cada carácter (y en los extremos), para tratar palíndromos de longitud par e impar exactamente igual.

Luego se recorre la cadena una sola vez manteniendo el centro C y el borde derecho R del palíndromo más lejano encontrado hasta ese punto.

Si la posición actual cae dentro de ese borde, su radio mínimo se copia por simetría del espejo — sin comparar carácter por carácter otra vez.

Pedro — Manacher

La clave: R nunca retrocede

Cada vez que una expansión tiene éxito, el borde R avanza. Nunca vuelve atrás. Eso significa que, sumando todas las expansiones de las 29,903 posiciones, el trabajo total sigue acotado por el tamaño de la cadena.

Un algoritmo de fuerza bruta prueba cada centro y expande desde cero: O(n²). Manacher reutiliza lo ya calculado y baja eso a O(n) — lineal.

for i in range(1, n-1):
    mirror = 2*C - i
    if R > i:
        P[i] = min(R-i, P[mirror])
    while T[i+1+P[i]] == T[i-1-P[i]]:
        P[i] += 1          # esto es lo único
                            # que cuenta como "trabajo nuevo"
    if i+P[i] > R:
        C, R = i, i+P[i]

El while sólo avanza R hacia adelante — por eso el total de pasos está acotado por n.

Ileana — Suffix Array

Verlo como buscar una subcadena común

Se construye T = S + "#" + reverso(S) + "$". Un palíndromo centrado en la posición i de S es, en T, una coincidencia entre el sufijo que empieza en i y su posición espejo del lado invertido.

Esa coincidencia se mide con el arreglo LCP (cuánto comparten dos sufijos consecutivos en el suffix array) y una sparse table que responde "¿mínimo LCP en este rango?" en O(1).

Ileana — Suffix Array

Construir, ordenar y consultar

Suffix array rank doubling + sort · O(n log² n)
LCP (Kasai) recorrido lineal · O(n)
Sparse table construir O(n log n) · consultar O(1)

El paso que domina es construir el suffix array: log n rondas de duplicación, cada una con un ordenamiento O(n log n). Total: O(n log² n).

O(n log² n)
tiempo total, dominado por el ordenamiento repetido de sufijos en cada ronda de duplicación
Marco — Palindrome SA

Misma idea, otra implementación

La versión de Marco resuelve el mismo problema con las mismas tres piezas — suffix array, LCP de Kasai y sparse table — pero construye el suffix array ordenando directamente tuplas (rank[i], rank[i+k]) en cada ronda, en vez de comparar contra un arreglo de claves aparte.

El resultado: complejidad idéntica en la teoría — O(n log² n) — pero una implementación distinta línea por línea. Buen recordatorio de que un mismo algoritmo admite varias formas correctas de escribirse.

segundo = rank[k:] + [-1]*k
clave = list(zip(rank, segundo))
sa.sort(key=lambda i: clave[i])
# ordena tuplas (rank[i], rank[i+k])
# directamente, ronda tras ronda

Verificado: sobre el genoma completo, las tres implementaciones encuentran exactamente el mismo palíndromo.

Pero el enfoque de suffix array no fue "peor" en general: su LCP + RMQ es un kit reutilizable para muchos otros problemas de cadenas — subcadenas repetidas, comparación entre múltiples secuencias, etc. Manacher está optimizado sólo para este problema.

Conclusiones

Tres formas de resolver el mismo problema

Especializar gana velocidad Manacher, hecho a la medida, es O(n) y el más rápido en la práctica
Generalizar gana alcance suffix array + LCP resuelve familias enteras de problemas de cadenas
