01 / DEFINICIÓN
EL PROBLEMA ABSTRACTO

Comparar y ordenar
subcadenas sin
leerlas letra por letra.

Comparar dos cadenas de longitud L, carácter por carácter, cuesta O(L). Un algoritmo que repite esa comparación miles de veces —búsqueda de patrones, deduplicación, ordenar sufijos, contar subcadenas distintas— arrastra ese costo en cada paso. Dos familias de técnicas resuelven esto desde ángulos distintos: hashing de cadenas (comparación) y suffix array (orden).

Entrada
→
Una cadena s de longitud n, y consultas repetidas sobre sus subcadenas o sufijos.
Salida
→
Igualdad, orden lexicográfico, posición de un patrón, o longitud de la subcadena repetida más larga — en tiempo sub-lineal por consulta.

01 / RELEVANCIA
POR QUÉ IMPORTAN LAS DOS

Dos ideas centrales.

El hashing mapea cada subcadena a un entero: cadenas iguales → mismo hash siempre; cadenas distintas → hashes distintos con altísima probabilidad. El suffix array, en cambio, ordena todos los sufijos de s lexicográficamente: no compara por igualdad, compara por orden — y de ahí se derivan búsquedas de patrón, subcadena repetida más larga y más.

ANTES / DESPUÉS
Fuerza bruta
O(n²·L)
Comparar todos los pares de subcadenas o sufijos exige recorrerlos cada vez.
Con hashing
O(1)
Un precómputo O(n) permite comparar cualquier par de subcadenas en tiempo constante.
Con suffix array
O(log n)
Una construcción O(n log n) permite ordenar, buscar patrones y calcular LCP eficientemente.

FUNCIÓN HASH POLINOMIAL

Rolling hash.

H(s) = (s₀·p⁰ + s₁·p¹ + … + sₙ₋₁·pⁿ⁻¹) mod m

p es un primo cercano al alfabeto (31, 53); m un módulo grande (1e9+7). El hash de s[l..r] sale por resta de prefijos en O(1):

hash(l, r) = (H[r] − H[l−1] · pʳ⁻ˡ) mod m

POR QUÉ DOBLE MÓDULO

Con un solo (p, m), la probabilidad de colisión es ~1/m. Con dos pares independientes, cae a ~1/m² — esa es la diferencia entre una implementación de examen y una robusta frente a un juez adversarial.

Rigor formal
→
El peor caso solo aparece si el adversario conoce p y m; aleatorizarlos en tiempo de ejecución lo neutraliza.

# StringHasher — doble módulo, O(n) precómputo, O(1) consulta
class StringHasher:
    def __init__(self, s, base1=131, mod1=10**9+7,
                 base2=137, mod2=10**9+9):
        self.n = len(s)
        self.mod1, self.mod2 = mod1, mod2
        self.h1 = [0]*(self.n+1); self.h2 = [0]*(self.n+1)
        self.p1 = [1]*(self.n+1); self.p2 = [1]*(self.n+1)
        # precómputo — O(n)
        for i, ch in enumerate(s):
            v = ord(ch)
            self.h1[i+1] = (self.h1[i]*base1 + v) % mod1
            self.h2[i+1] = (self.h2[i]*base2 + v) % mod2
            self.p1[i+1] = (self.p1[i]*base1) % mod1
            self.p2[i+1] = (self.p2[i]*base2) % mod2
    def get_hash(self, l, r):
        # hash de s[l:r) — O(1)
        h1 = (self.h1[r] - self.h1[l]*self.p1[r-l]) % self.mod1
        h2 = (self.h2[r] - self.h2[l]*self.p2[r-l]) % self.mod2
        return (h1, h2)
    def equal(self, l1, r1, l2, r2):
        if (r1-l1) != (r2-l2): return False
        return self.get_hash(l1,r1) == self.get_hash(l2,r2)

05 / FUNDAMENTOS
DEFINICIÓN

Todos los sufijos, ordenados.

El suffix array SA de una cadena s de longitud n es la permutación de los índices 0..n−1 tal que los sufijos s[SA[0]:], s[SA[1]:], … quedan ordenados lexicográficamente. En vez de comparar por hash, se compara por orden real de caracteres.

Construcción por duplicación de rango (Manber–Myers): en la iteración k, se ordena por los primeros 2ᵏ caracteres, duplicando k en cada paso hasta cubrir n.

POR QUÉ IMPORTA EL LCP

El suffix array por sí solo ya cuesta O(n log n) construirlo; el LCP array (longest common prefix entre sufijos consecutivos) se calcula en O(n) adicional con el algoritmo de Kasai, y desbloquea consultas como la subcadena repetida más larga sin costo extra por consulta.

Determinismo
→
A diferencia del hashing, el resultado es siempre exacto: no hay probabilidad de error.

# Suffix array por duplicación de rango — O(n log n)
def build_suffix_array(s):
    n = len(s)
    sa = list(range(n))
    rank = [ord(c) for c in s]
    k = 1
    while True:
        def key(i):
            nxt = rank[i+k] if i+k < n else -1
            return (rank[i], nxt)
        sa.sort(key=key)  # O(n log n) por iteración
        tmp = [0]*n; tmp[sa[0]] = 0
        for i in range(1, n):
            tmp[sa[i]] = tmp[sa[i-1]] + (key(sa[i]) > key(sa[i-1]))
        rank = tmp
        if rank[sa[-1]] == n-1 or k > n: break
        k *= 2
    return sa

# LCP array — algoritmo de Kasai, O(n)
def kasai_lcp(s, sa):
    n = len(s); rank = [0]*n; lcp = [0]*n; h = 0
    for i, p in enumerate(sa): rank[p] = i
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i]-1]
            while i+h<n and j+h<n and s[i+h]==s[j+h]: h += 1
            lcp[rank[i]] = h
            if h > 0: h -= 1
    return lcp

Dos funciones, dos complejidades.

build_suffix_array
O(n log n)
log n iteraciones, cada una ordena en O(n log n) usando ranks de la iteración anterior.
kasai_lcp
O(n)
Explota que h nunca baja más de 1 entre iteraciones consecutivas — amortizado lineal.
